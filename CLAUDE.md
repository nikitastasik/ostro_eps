# Правила хакатона (обязательны для всего кода в репозитории)

## Репозиторий
- Код только в репозитории команды в организации https://github.com/orgs/ostrovok-hackathon-2026/.
- Обязательные файлы в корне: `README.md`, `docker-compose.yml`, `Dockerfile` (по одному на сервис), `.env.example`.
- Сдача: git-тег `submission` на последнем коммите основной ветки к дедлайну.
- Никаких приватных зависимостей/реестров. Большие артефакты/модели не хранить в git — использовать OpenAI-совместимое API.

## Запуск (проверяется жюри)
- `git clone` → `cd <repo>` → `cp .env.example .env` → `docker compose up --build` (без доп. аргументов) → http://localhost:8080.
- Никаких ручных доустановок кроме Docker/Compose и копирования `.env`. Развёртывание ≤10 минут.
- Миграции и сидирование — автоматически на старте контейнера (или 1–2 команды в README).

## Docker
- Все сервисы (приложение, БД, кэш и т.д.) в Docker.
- Приложение внутри контейнера слушает 8080, в Compose проброс `8080:8080`.
- Multi-stage build, лёгкий рантайм-образ без dev-инструментов.
- Процесс под непривилегированным пользователем (не root).
- Секреты только через `.env`/`env_file`/docker secrets, реальные секреты не коммитить.
- `/health` в приложении → 200, `{"status":"ok"}`; healthcheck в Compose; `depends_on` с `condition: service_healthy`.
- `platform: linux/amd64` для сервисов.
- Фиксированные версии базовых образов и зависимостей (без `latest`).
- Логи в stdout/stderr.
- В рантайме контейнера только POSIX sh, без bash-специфики.

## README.md (по шаблону)
1. `# Название (трек)` + 1–2 предложения что делает; ссылка на видео-скринкаст (обязательно), ссылка на деплой (опц.).
2. Быстрый старт: команды от `git clone` до `localhost:8080`.
3. Зависимости и переменные окружения: ресурсы (CPU/RAM), сервисы (БД, кэш), все переменные с дефолтами.
4. Сидирование: как загрузить демо-данные.
5. Маршруты/доступ: `/`, `/health`, тестовые учётные данные.
6. Если нет UI: точные команды, формат входа, пример вызова и вывода.

## Рекомендуется
- `Makefile`: `make up`, `make down`, `make seed`.
- `docker-compose.override.yml` для локальной разработки.
- CI: `docker build` + линтер.
